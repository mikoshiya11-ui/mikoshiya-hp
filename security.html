セキュリティ / トラスト

安心して使える仕組みを、
最初から。

システムは、動くだけでは足りません。
大切な業務と情報を守りながら、
安心して使い続けられる設計を行います。

MIKOSHIYAのセキュリティ設計

OUR SECURITY
  • 01

    認証・権限管理

    • 個人アカウントでの利用
    • ロールベース権限（RBAC）
    • 最小権限の原則（Least Privilege）
    • 管理権限の分離
    • セッション管理
    • 不要アカウント停止
  • 02

    データ保護

    • HTTPS / TLSによる暗号化通信
    • 保存データの保護
    • 顧客データの論理分離
    • APIキー / Secret等の分離管理
    • バックアップ / 復旧設計
  • 03

    データベースセキュリティ

    • Row Level Security（RLS）
    • DB側でのアクセス制御
    • ユーザー単位の権限制御
    • UPDATE / DELETE範囲の制限
    • 入力値制約・整合性チェック
  • 04

    ネットワーク・通信

    • TLS暗号化通信（HTTPS）
    • 必要な通信のみ許可（Firewall）
    • LAN限定構成への対応
    • 通信経路・接続先の制御
    • 現地環境・閉域ネットワークへの対応
  • 05

    開発・リリース管理

    • Gitによる変更管理
    • Pull Requestによるレビュー
    • CIによる自動検査
    • Previewでの事前確認
    • 本番環境と開発環境の分離
    • リリース前後の動作確認・整合性確認
  • 06

    AI利用時の情報管理

    • 機密情報を無条件にAIへ送らない
    • 利用するAI・クラウドを明確化
    • 必要なデータのみを扱う
    • APIキー / Secretの分離管理
    • AI出力をそのまま本番反映しない
    • 人による確認・承認プロセスを設ける
  • 07

    運用・障害対応

    • システムログの取得・確認
    • 定期バックアップと復旧手順
    • 権限変更・アカウント停止の運用
    • 運用状況の定期確認
    • 障害時の切り分けと復旧対応
    • 継続的な改善
